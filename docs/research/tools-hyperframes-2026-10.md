# HyperFrames vs our studio pipeline (research, read-only; nothing installed or run)

Repo: /home/user/heygen-com/hyperframes (HeyGen, "Write HTML. Render video. Built for agents."). Read: README, CLAUDE.md, docs/concepts+guides+packages, packages/{lint,engine,shader-transitions,cli} metadata, skills/*, registry/*, CREDITS.md. I did NOT build or run it (no node_modules; no bun install attempted), so every speed or behaviour claim below is from its docs/source, not measured.

## 1. What it is, architecture, rendering, licence, install

- Monorepo (bun workspaces, TypeScript): `packages/{core,engine,producer,cli,lint,parsers,player,studio,studio-server,shader-transitions,sdk,aws-lambda,gcp-cloud-run}`, plus `skills/` (21 agent skills), `registry/` (blocks + components), `themes/`, `docs/` (Mintlify).
- Authoring model: an HTML file. Timing by `data-*` attributes (`data-composition-id`, `data-start`, `data-duration`, `data-track-index`, `class="clip"`, `data-width/height/fps`). Motion by one paused GSAP root timeline registered on `window.__timelines[compositionId]` (also CSS keyframes, WAAPI, Anime.js, Lottie, Three.js, TypeGPU adapters). Output MP4/MOV(ProRes 4444)/WebM(alpha)/GIF/PNG-seq/HLS (docs/guides/rendering.mdx).
- Rendering (docs/concepts/determinism.mdx, docs/packages/engine.mdx): headless Chrome (Puppeteer, `chrome-headless-shell`), page must expose `window.__hf` with `duration` and `seek(time)`. Per frame: `time = floor(frame)/fps` (integer math) -> adapter `seekFrame` -> Chrome `HeadlessExperimental.beginFrame` atomic capture -> frames stream into FFmpeg; audio from `<audio>/<video>` mixed by FFmpeg. Same idea as ours (`window.render(t)` + toDataURL in studio/engine/render.mjs).
- GPU: not required. `--browser-gpu/--no-browser-gpu` ("Hardware GPU capture, or deterministic SwiftShader", default off in Docker); `--gpu` is only for hardware FFmpeg encode. WebGL shader transitions fall back to plain timeline playback if WebGL missing (so SwiftShader needed on CPU, slow).
- Parallelism: `--workers 1-24`, each a separate Chrome ~256 MB; auto-chosen. Streaming BeginFrame capture on Linux with bundled chrome-headless-shell, DPR 1.
- Speed numbers documented: almost none. docs/guides/performance.mdx: one CSS fix took a 1920x1080, 300-frame composition from 25.0 s to 9.8 s (median of 3, their machine). `--page-side-compositing` "~6x faster" for shader transitions; `--experimental-fast-capture` "~2x faster". No CPU-only frames/s figure. Expect screenshot-class cost per frame (our canvas `toDataURL` path is likely as fast or faster, unmeasured).
- Licence: root LICENSE Apache-2.0; every package.json checked says Apache-2.0. No closed binaries in the repo. Third-party: GSAP 3.14.2 under the GSAP Standard License ("not an OSI open-source licence"; free incl. commercial but restricted from building competing visual-animation tools), mediabunny MPL-2.0 (studio only), Parakeet model CC-BY-4.0, Three.js MIT, fonts OFL. Catalog blocks load GSAP/d3/topojson/world-atlas/Google Fonts from CDNs (see risks).
- Install: Node >=22 (`engines`), FFmpeg, Chrome (auto-downloaded via `@puppeteer/browsers` / `hyperframes browser ensure`, network at install). Dev builds use bun (CLAUDE.md: "bun install ... NOT pnpm"), end users just `npx hyperframes`. Our container already has node 22.22 and bun, so install is plausible. Offline after install: yes in principle (determinism rules forbid render-time fetches; the compiler pre-bundles 18 fonts as data URIs), but first-use model downloads (Kokoro, Parakeet/whisper.cpp build) and CDN script tags in blocks need network or vendoring. Parakeet needs glibc >= 2.32 on Linux.

## 2. Determinism vs ours

Essentially the same contract: frame = pure function of t; no `Date.now`, no unseeded `Math.random`, no `requestAnimationFrame`, no render-time fetch, fixed fps/size before frame 0. Differences:
- Theirs is retained-mode (DOM + paused GSAP timelines seeked) and relies on adapters; ours is immediate-mode canvas with our own `hash()/rnd()`. Ours is stricter by construction (nothing to forget to seek); theirs needs lint to enforce it (see 6).
- They admit residual env variance: "Exact pixels can still vary with Chrome, fonts, codecs, GPU behavior"; offered fix is `render --docker`.
- Adapter interface (`FrameAdapter`: `init/getDurationFrames/seekFrame/destroy`) is "experimental v0" (docs/concepts/frame-adapters.mdx). A Three.js/Lottie/GSAP adapter set ships built in.
- A hosting contract for any page: expose `window.__hf = {duration, seek(t)}`. In principle our `window.render(t)` page could be rendered by their producer with a ~10-line shim, but we gain nothing we do not already have.

## 3. Audio

- TTS: `hyperframes tts` = local Kokoro-82M, "No API key, nothing leaves the machine" (docs/packages/cli.mdx L330). Voices by prefix (a/b English US/UK, etc.), `--speed`. Free and offline after model download. Quality is below Fish; comparable class to Piper (we use Piper en_US-ryan-high for drafts). media-use also offers HeyGen TTS "free-usage path" via `heygen auth login --oauth` (HeyGen service, account-bound credits, not unlimited-free guaranteed). No ElevenLabs/OpenAI wiring found in the skill text I read.
- Transcription/word timing: `hyperframes transcribe` -> Parakeet TDT 0.6B v3 (sherpa-onnx int8, CC-BY-4.0) or whisper.cpp fallback (models `small.en/medium.en/large-v3`); imports .srt/.vtt/JSON. Word-level JSON drives captions. We already have faster-whisper word times plus a WER gate; no gain, except Parakeet may be more accurate/faster on CPU (unverified).
- Captions: lint rules and 30+ `caption-*` components (kinetic-slam, pill-karaoke, highlight, glitch-rgb, emoji-pop, weight-shift, camera-follow...). Rule `asr-keyword-glow`: word-timestamp-driven glow envelope. Our captions are canvas-drawn, so only the design ideas transfer.
- Music: `media-use` resolves BGM/SFX from a HeyGen catalog (needs `heygen` CLI + sign-in) or generates (Lyria via Gemini; paid/key). No offline music generator. Our code-synthesized score is the free path.
- Beat sync: `hyperframes beats` (decodes music in headless Chrome, BPM + per-beat strength -> `beats/<audio>.json`); `music-to-video` skill; `audio-reactive.md`; rule `kinetic-beat-slam`. Useful if we ever sync to our synthesized music; our pipeline syncs to spoken words, which it already does better.
- Mix: `hyperframes-audio` skill and `<hf-audio-group>`: voiceover "carve" (dip music only in voice bands), EQ/comp/limiter/reverb chain, automation envelopes, `normalize-audio`. Our ducking is simple sidechain-style; the band-carve idea is an upgrade. Implementation is Web Audio/FFmpeg inside their producer, not extractable trivially.

## 4. Skills: knowledge worth stealing (rules we lack)

Skills are Markdown (+ small scripts), so cheap to read and port. Highest-value items:
1. skills/hyperframes-creative/references/motion-principles.md "Guardrails" (aimed at LLM agents, which is exactly our Sonnet storyboard fillers): no same ease on every tween (max 2 per scene), slowest scene >= 3x the fastest, vary entry direction, vary stagger per scene, do not start at t=0 (offset 0.1-0.3 s), stillness after motion. Direction rules: `.out` enter, `.in` exit, `.inOut` move; exits faster than entrances (0.4 s in / 0.25 s out); group stagger total <= ~0.5 s; build/breathe/resolve phases (0-30 / 30-70 / 70-100%); transitions are meaning (crossfade = continues, hard cut = disruption).
2. Same file, composition: "two focal points minimum", "three layers minimum" (background treatment, foreground, accent), fill the frame (hero text 60-80% width), background never empty, anchor to edges, structural lines must name start/end anchors or be cut.
3. data-in-motion.md: pair every number with a visual (fill bar/ring); no pie charts, no multi-axis, no gridlines/tick marks/legends; keep successive stats in the same visual space, only the value changes. Directly relevant to LeaderFlags.
4. beat-direction.md: describe the experience of each beat, not pixels; motion-verb vocabulary (SLAMS/DRAWS/COUNTS UP...), velocity-matched transitions, SFX cue planning. Good for our `05-storyboard.md` playbook prompts.
5. narration.md: "2.5 words/s", script should feel shorter than the video, spell numbers as spoken (table), hook patterns, "no generic opener". We have most; the pronunciation table is a cheap check.
6. typography.md: video sizes not web sizes (body >= 20 px, headlines 60 px+ on 1080p; in-feed viewing section), extreme weight contrast (300 vs 900), one expressive font per scene, banned monoculture fonts. Our fixed Anton/Elite/DM Serif bibles already comply.
7. hyperframes-animation/rules (55 atomic recipes, each with a seek-safety contract) and blueprints (22): the contract list is a good lint checklist: fromTo with explicit from-state, no relative `+=` tweens, no CSS transition on animated elements, no width/height/top/left tweens, finite repeats, hash on quantized time for glitch.
8. keyframes skill: "pose contract" (name the subject, the visible states, the final state; do not reset to rest; do not end on black) and `hyperframes keyframes` diagnostic for verifying rendered motion.
9. check's `--caption-zone` idea (see 6) and persistence-aware severity.
10. Transitions: skills/hyperframes-animation/transitions (CSS catalogs: push/cover/blur/radial/grid/mechanical/dissolve/destruction/distortion/light) + the shader list.

## 6. Lint / QA tooling

- `hyperframes lint` (packages/lint, 121 distinct rule codes, severity error/warning/info, `--json`, `fixHint` per finding, library API `lintProject`, browser-safe `lintHyperframeHtml`). Static checks on composition HTML: missing timeline registration, non-deterministic code (`non_deterministic_code`, `requestanimationframe_in_composition`), `css_transition_used`, `gsap_infinite_repeat`, relative-value second writer, cold-seek hazards (`gsap_cold_seek_hidden_fromto_missing_reveal`), `gsap_non_transform_motion`, overlapping tweens, undefined CSS variables, font without @font-face, caption overflow/exit-kill checks, media attrs, duplicate IDs, base64 media prohibited, placeholder URLs, root dimension mismatches. It lints HTML/GSAP, so it cannot run on our canvas-engine output at all. Adoptable only as a checklist for our scene code (e.g. forbid `Date`, `Math.random` in studio/engine and scenes.js; we likely have this).
- `hyperframes check` (browser gate, one Chrome session, `--json` envelope; every finding carries selector, bbox, sample time): sweeps a seek grid (`--samples` 9, `--at`, `--at-transitions`) running: console errors/failed requests, layout (overflow, clipping, held overlaps, occlusion, off-frame), WCAG AA contrast with measured ratio and a suggested compliant colour, `--caption-zone` band gate (flags text DOM boxes overlapping a fractional band, i.e. platform UI/caption zone), `--frame-check`, `sweep_static` (timeline that never moves in >= 3 s composition fails), persistence-aware severity (a single-sample finding demotes to info), `data-layout-allow-*` opt-outs, and `*.motion.json` assertions (`appearsBy`, `before`, `staysInFrame`, `keepsMoving` with `maxStaticSec` default 2 s; `motion_frozen`).
- Reads DOM boxes, so it cannot audit a single `<canvas>`. For our output the portable ideas are pixel-level: (a) frozen-window detector = frame-diff over the sampled JPEGs, flag > 2 s static; (b) caption-zone/safe-zone overlap using our own scene geometry (we typeset text in code, so we know the boxes: have the engine emit text rects per frame to `engine_report.json`); (c) WCAG contrast computed from the rendered pixels behind each text box; (d) "appears by" assertions derived from word cues (event word time + reveal must be visible within N ms). These fit our gate model (deterministic python).
- `hyperframes keyframes`: lists GSAP/CSS/Anime.js keyframes detected plus `--shot`; HTML-only.
- `snapshot`, `compare`, `grade-compare`, `doctor` also exist.

## 7. Verdict

(a) Adopt wholesale as renderer: NO. Reasons: our canvas engine already meets the same determinism contract with a smaller, controllable surface; our scene types (real-data maps, flag badges, organ characters, paper-cutout) would all have to be rewritten as DOM/SVG/GSAP, losing the catalog+gates model (storyboard.json -> engine); their render is Chrome screenshot/BeginFrame + FFmpeg, no faster on CPU; GSAP Standard License is a non-OSI dependency; the Sonnet-fills-a-catalog workflow would become Sonnet-writes-HTML/GSAP, which is the failure mode our design avoids. Cost: weeks, with regression risk.

(b) Adopt specific pieces (ranked by value/effort):
1. Port the motion/composition guardrails (items 1-3, 5 in section 4) into `studio/sop/05-storyboard.md` and `06-picture.md` and into catalog `_doc`/bibles; add scene-level gates: ease variety per scene (we control the engine, so log ease names per scene in `engine_report.json` and flag > 2 same), min duration spread, no-event-at-t=0, group stagger <= 0.5 s. Effort: 0.5-1 day. Pure text/Python, zero risk.
2. Add `check`-style audits to our gates: frozen-window (frame diff, > 2 s static), caption/safe-zone overlap from engine-emitted text rects, WCAG contrast on rendered pixels, off-frame, "appears by" from word cues. Effort: 1-2 days.
3. Voiceover "carve" ducking (duck music only in voice bands via EQ notch/multiband rather than broadband gain) in `*/tools/audio.py`: reimplement with ffmpeg `equalizer`/`sidechaincompress` + band split. Effort: 0.5 day. Read skills/hyperframes-audio/SKILL.md for the parameters.
4. Try Kokoro (`npx hyperframes tts`) and Parakeet as free narration/ASR alternatives to Piper/faster-whisper: benchmark on a 40 s script (WER, naturalness cannot be judged by us). Requires network once for model download. Effort: 0.5 day to evaluate; adopt only if WER on our gate beats faster-whisper.
5. GLSL fragments from shader-transitions (domain-warp, whip-pan, glitch, light-leak, iris) as new transition types in our canvas engine (WebGL in canvas under SwiftShader, or reimplement as 2D canvas ops). Effort: 1-2 days per 3-4 transitions; check CPU frame cost first.
6. Motion references for new catalog scene types: `bar-chart-race` easing/overtake logic, `slot-machine-roll`, `split-flap-board`, `hw-boil`/`stop-motion-cadence` (boil on quantized time for paper-cutout), `torn-paper-rip`, `paper-collage-reveal`, `caption-pill-karaoke`, `caption-kinetic-slam`. Effort: ~0.5 day per scene type to re-implement in canvas.
7. Optional: `hyperframes beats` idea (beat times from music) only if we decide to cut to music; `kinetic-beat-slam` rule for a "punchy" scene type.

(c) Only borrow ideas: pose-contract ("do not end on black; final frame is part of the animation"), persistence-aware lint severity, `data-layout-allow-*` style opt-outs for deliberate overlaps (we have a similar need for intentional occlusion), `variables` schema for parameterized scenes, `*.motion.json` sidecar assertion format as a model for a `storyboard.assert.json`.

(d) Skip: Studio editor, player, SDK, avatar/HeyGen presenter and `heygen` CLI paths, cloud/Lambda render, HDR/color grading, product-launch/pr-to-video/slideshow/figma/remotion workflows, theme CSS, 3D/liquid-glass UI blocks, Remotion migration.

## Risks
- Lock-in/dependency: GSAP Standard License; HyperFrames API labelled experimental (v0 adapter interface); fast release cadence (weekly updates, canary rollouts). Pin a version if used at all.
- Telemetry: on by default (command names, render perf, OS/CPU/memory shape, sandbox runtime e.g. gVisor/Docker, name of coding agent such as `claude_code`; project names/content not collected). Disable with `HYPERFRAMES_NO_TELEMETRY=1`. Docs note turning it off also opts out of canary rollouts. `init` also checks skills against GitHub and may auto-update global skills; never run `npx skills add --all` inside the checkout.
- Network: CLI install downloads Chrome and models; `skills update` pulls from GitHub; media-use catalog/TTS/BGM go to HeyGen services (sign-in, credits); many blocks load GSAP/d3/topojson/world-atlas/Google Fonts from CDNs (world-map fetches countries-110m.json at runtime). These violate "offline, deterministic, no paid APIs" unless vendored. The core compiler does inline 18 fonts offline.
- Runtime fit: Kokoro/Parakeet need local model downloads, glibc >= 2.32; WebGL shaders on CPU depend on SwiftShader; each worker is a full Chrome (~256 MB).
- Our fonts (Anton, Special Elite, DM Serif Display) are not in their 18 bundled fonts; they would need @font-face embedding.
- Unverified by me: actual install success in this container, CPU frame rates, Kokoro quality, Parakeet WER.

## One-line recommendation
Do not switch renderers. Spend ~3-4 days importing the production rules (as SOP text plus engine-side gates: ease variety, frozen window, caption-zone, contrast, appears-by-cue), the voiceover-carve ducking, and a few shader/handwriting transitions; benchmark Kokoro/Parakeet as optional free alternatives.
